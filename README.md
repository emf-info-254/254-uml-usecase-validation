# 🧩 Module 254 — Évaluation sommative : cas d’utilisation UML

## 🎯 Objectif
Modéliser les interactions entre les acteurs et un système
à l’aide d’un diagramme de cas d’utilisation.

## 📋 Consignes
Cet exercice est à rendre à votre maître professionnel pour validation

Le responsable de SportConnect, M. Luis Carrare, gère le centre sportif proposant différentes activités. il vous contacte pour développer une plateforme de réservation en ligne.

Actuellement, les réservations se font par téléphone ou directement à l’accueil. Cette organisation devient difficile à gérer étant donné l’augmentation du nombre de clients.

Lors d’un entretien, M. Carrare vous explique ses besoins :

- Les visiteurs pourront consulter les activités proposées par notre centre sans devoir créer un compte obligatoirement.
- Lorsqu’une personne souhaite réserver une activité, elle doit être détentrice d’un compte pour se connecter à la plateforme et devient cliente de SportConnect.
- Lors de la réservation, le système doit vérifier la disponibilités des places et lorsque c’est complet, le client peut s’inscrire sur la liste d’attente.
- Lorsque la réservation a abouti, le client reçoit automatiquement une confirmation de réservation
- Certains clients possèdent un abonnement Premium, ils bénéficient alors d’une réduction lorsqu’ils réservent une activité.
- Un client peut annuler ses réservations. Lorsqu’une place se libère, les personnes inscrites sur la liste d’attentes sont averties.
- Les moniteurs qui animent des activités vont consulter la listes des clients participants et signaleront les clients absents.
- Les collaborateurs de l’accueil et M. Carrare pourront ajouter des nouvelles activités, modifier les horaires, les tarifs et les nombres de places disponibles. Ils pourrons aussi supprimer une activité lorsqu’elle n’est plus proposée.
- M. Carrare souhaite pouvoir consulter les statistiques de fréquentation de SportConnect.

## Travail demandé
1. Identifiez les acteurs qui interagissent sur la plateforme
2. Identifiez les cas d’utilisation
3. Identifiez les relations entre les cas d’utilisation
4. Réalisez le diagramme de cas d’utilisation (UML) → USE CASE
5. Représentez les associations entre les acteurs et les cas d’utilisation  en intégrant les relations <<include>> et <<extend>> lorsqu’elles sont justifiées.

🛠️ Utilisez **Visio** pour la création du USE CASE
